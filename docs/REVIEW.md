### Архитектурное ревью

Сильные стороны
- Архитектура разбита на независимые компоненты: CLIInterpreter, CLIParser, Command, Value/Argument. Также есть вспомогательные объекты (StreamConfig, Environment, ReturnCode). Это способствует легкой поддержке и расширяемости кода
- Есть разграничение зон ответственности 
  - CLIInterpreter отвечает за основной цикл обработки команд и взаимодействие с потоками
  - CLIParser занимается исключительно синтаксическим разбором ввода
  - Command реализует абстракцию команд, а наследники - конкретную логику по каждой команде
  - Value/Argument отвечают за обработку и подстановку переменных
- Хорошая работа с потоками ввода/вывода/ошибок
- Описана точка входа программы, что помогает понять полный жизненный цикл программы
- Тестируемость, потому что хорошее разграничение зон ответственности

Слабые стороны (их немного и они маленькие)
- Все команды пайплайна пишут ошибки в общий поток stderr. В сложных пайплайнах это затруднит отладку, так как непонятно, какая команда выбросила ошибку
- Не дописан процесс выполнения пайплайнов
- Не описано как запускать приложение и тесты

В процессе выполнения задачи не возникло никаких проблем, из-за хорошей архитектуры решение задачи получилось небольшим. 
Единственное, пришлось вспомнить как не из idea запускать проект
